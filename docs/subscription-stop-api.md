# 停止订阅接口

接口均需使用已登录的管理员会话。订阅页已接入单个与批量停止入口：

- 在卡片的更多菜单或右键菜单中选择“停止订阅”，停止对应来源。
- 在“添加订阅”后的“批量操作”下拉菜单中选择“停止订阅”，勾选目标后提交；支持全选，每次最多 100 个。
- 停止成功后卡片显示“已停止”，刷新与重复停止入口禁用；批量请求失败时保留选择供重试。

## 单个停止

`POST /api/v1/feeds/{source_id}/stop`

不需要请求体。成功返回 HTTP 200，响应结构与 `GET /api/v1/feeds` 中的单个 `FeedRead` 相同，其中 `active` 为 `false`。重复停止同一个订阅仍返回成功。

## 批量停止

`POST /api/v1/feeds/batch-stop`

```json
{
  "source_ids": [1, 2, 3]
}
```

`source_ids` 必填，包含 1–100 个正整数；不接受字符串、布尔值或小数。重复 ID 自动去重，响应中的 `items` 保持首次出现的顺序。

成功返回 HTTP 200，响应字段如下：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `items` | `FeedRead[]` | 各订阅的完整对象，`active` 均为 `false` |
| `stopped_count` | 整数 | 本次从启用变为停止的订阅数 |
| `already_stopped_count` | 整数 | 原本已经停止的订阅数 |

两个计数之和等于去重后的 ID 数量。

整批先校验再提交。任一 ID 不存在时返回 HTTP 404，所有订阅均保持原状：

```json
{
  "detail": {
    "message": "部分订阅不存在",
    "source_ids": [999]
  }
}
```

单个停止的 ID 不存在时使用相同错误结构。未登录返回 HTTP 401，批量参数无效返回 HTTP 422。

## 停止后的行为

- 复用已有 `FeedSource.active=false`，保留订阅、元数据、已发现条目、下载记录和文件，适用于所有来源类型。
- 定时刷新跳过已停止的订阅；手动刷新停止的 RSS 订阅返回 HTTP 409。正在等待网络或解析的 RSS 刷新会在入库前检查最新状态，丢弃停止后的响应。
- 停止与 RSS 入库、下载入队共用队列锁。停止后不再自动新增下载；仅在状态实际改变时发布 `feed.updated` 事件，事件包含 `active=false`。
- 沿用已有停用语义：Mooncell 暂停该订阅普通下载任务的后续自动处理；媒体库迁移、单集改名仍按原有规则处理。接口不向 qBittorrent 发送暂停或删除请求，已投递任务在下载器中的运行状态由下载器保持。
- 后续可以使用已有 `PATCH /api/v1/feeds/{source_id}`，传入 `{"active": true}` 恢复订阅及其自动处理。
